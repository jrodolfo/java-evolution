# Hidden Classes

Java 15 introduced hidden classes in JEP 371.

This is an explanatory learning module. It does not generate bytecode because a faithful hidden-class example usually belongs to framework or runtime code that creates class bytes dynamically and defines them with `MethodHandles.Lookup.defineHiddenClass`.

## 1. What Problem Does This Feature Solve?

Some Java code creates implementation classes at runtime.

Examples include:

- proxy libraries
- expression engines
- dynamic language runtimes
- serialization frameworks
- lambda and method-handle infrastructure

These generated classes are usually implementation details. Application code should not find them by name, depend on them, or treat them as part of a stable API.

Before hidden classes, generated classes were often more visible and name-addressable than they needed to be.

## 2. How Was This Commonly Done Before?

Frameworks that needed runtime classes commonly generated bytecode and defined ordinary classes.

Conceptually:

```text
framework decides it needs an implementation class
    -> framework generates bytecode
        -> framework defines a normal class
            -> class may be visible by name
```

That works, but it is not always a good fit.

If the generated class is only an internal implementation detail, normal class discoverability can be undesirable.

## 3. What Did Java Introduce?

Java 15 added hidden classes.

A hidden class is still a real class to the Java Virtual Machine (JVM), but it is not intended to be found through normal class-name lookup.

At a high level, the workflow is:

```text
generate class bytes
    -> call MethodHandles.Lookup.defineHiddenClass(...)
        -> receive a hidden class for internal runtime use
```

The primary API is:

```java
MethodHandles.Lookup.defineHiddenClass(...)
```

## 4. Terminology In Plain English

Generated class:

A class created by a framework or runtime while the application is running, rather than written directly as a `.java` source file.

Bytecode:

The compiled class-file instructions that the JVM executes.

Normal class lookup:

Finding a class by its binary name through the usual class-loading mechanisms.

Hidden class:

A dynamically defined class that is intended for runtime implementation details and is not discoverable through normal name lookup.

`MethodHandles.Lookup`:

An object that represents lookup privileges. Hidden classes are defined through a lookup object so access rules are explicit.

## 5. Why This Repository Uses Notes

A meaningful hidden-class demo needs class bytes.

Those bytes usually come from:

- a bytecode library
- a compiler
- generated class-file data
- framework internals

Adding that machinery here would distract from the Java 15 feature.

A fake example that only returns a string containing API names would not demonstrate hidden classes. It would only test the string.

So this package explains the feature and tests the learning claims instead of pretending to generate classes.

## 6. What The Test Proves

`HiddenClassesNotesTest` does not define a hidden class.

It verifies that the notes preserve the important study points:

- generated classes can be implementation details
- hidden classes are not discoverable by normal name lookup
- the primary API is `MethodHandles.Lookup.defineHiddenClass`
- realistic users include frameworks, proxies, expression engines, and runtimes
- this repository intentionally avoids bytecode-generation machinery

## 7. Realistic Use Case

Imagine a framework that creates a proxy implementation for one specific call site.

The generated class exists so the framework can run efficiently, not so application code can import it, instantiate it, or depend on its name.

Hidden classes give such frameworks a better fit for runtime implementation details.

## 8. When Not To Use It

Do not use hidden classes for ordinary application models, services, controllers, or data classes.

If you are writing normal Java source code, use normal classes, records, interfaces, and packages.

Hidden classes matter when you are building infrastructure that generates runtime implementation classes.

## 9. Remember This

Hidden classes are for runtime-generated implementation details. They let frameworks define classes that the JVM can use without making those classes discoverable as normal named application classes.
